====================================================================================================
INSIGHTS OF THE WHOLE PROJECT: REAL DATA, SYNTHETIC DATA, AND BOTH TOGETHER
Technical debt: which debt to repay first, and how to test that ranking
====================================================================================================

HOW TO READ THIS FILE
---------------------
Every insight has the same fields:
    STATEMENT   what is true, in one or two sentences
    EVIDENCE    the numbers
    DATA        REAL | SYNTHETIC | BOTH | DISAGREE | COMBINED
    STRENGTH    STRONG        large effect, interval clear of zero, or the same answer in several tests
                MODERATE      clear direction, small sample or interval touches zero
                LEAD          suggestive only (p near 0.05, one test among several)
                BY DESIGN     a property built into the generator of the synthetic data; it confirms
                              the generator, it is NOT evidence about developers
    FIGURE      the picture(s) that show it (paths start from final_folder/presentation/new_figures/)
    SOURCE      where the numbers are computed (paths start from final_folder/)

Short names for the figure folders:
    01 = 01_dataset_creation   02 = 02_real_results   03 = 03_synthetic_dataset
    04 = 04_insights           05 = 05_new_experiments 06 = 06_combined

The two datasets
    REAL       61 clean/debt project pairs (10 open-source projects; 60 injected + 1 natural) with
               183 injected bugs and 133 features per pair; and the git histories of 9 repositories,
               20 releases each (1,540 debt instances, 20,582 instance-release rows, about 1,600
               interest events, 10.52 person-months of interest in total).
    SYNTHETIC  150 generated Python projects in 150 domains with simulated git histories
               (148,706 lines, 2,038 releases, 22,384 commits), 1,321 injected debt instances,
               11,927 instance-release rows, 1,806 interest events (4.14 person-months), 1,321
               parent/child commit pairs. 90 baseline projects follow the patterns of the real data;
               15 each are in four counter-regimes (sticky, ar_clock, decay, contagion).
    The real data are the evidence. The synthetic data are a testbed with known truth.


====================================================================================================
0. THE TEN THINGS TO REMEMBER
====================================================================================================
 1. Interest is a persistent hot-spot property: about half of the debt is never touched, a few
    percent absorbs most of the work, and an instance that paid before pays again with the same
    chance 1 to 6 releases later.                                                       [A1, A2]
 2. Developers avoid debt: debt regions are a third of the code but receive about an eighth of the
    edits.                                                                                   [A3]
 3. Region SIZE predicts interest as well as the history does: "largest function first" ties the
    "interest already paid" baseline; frozen debt is small debt.                        [R1, R2]
 4. The ranking is stuck at what size and history already say; the release clock is calibration,
    not timing.                                                                   [A5, A6, R6, R9]
 5. A clean twin (the parent commit) is what makes a debt change visible; a single snapshot cannot
    see it.                                                                                  [A7]
 6. Models learn the TEMPLATE of an injected change, not the debt: code-as-image CNNs, patch words
    and features all fall when the template is new.                                          [A8]
 7. A file-level graph or image sees only structural debt.                                   [A9]
 8. "The classifier does not generalise to new projects" was one project (boltons) and depends on
    the model; the time-feature gain depends on the time model.                         [R7, R8]
 9. The synthetic benchmark is NOT yet a proxy for the real pairs: its debt changes are 44 times
    larger, it has no size effect, and nothing trained on it works on real data; pooling it into
    training does not help.                                                     [D1, D2, C2, C3]
10. Adding the time series of the git history (features or a CNN) adds nothing on the real data
    beyond events, age and size.                                                        [A11, R10]

Which of these are out of the box, and what to do next for each: see PART J at the end.

A1  Interest is extremely concentrated and about half of the debt is frozen
    STATEMENT  A minority of the debt instances absorbs most of the interest; roughly half never
               receives any.
    EVIDENCE   REAL: Gini 0.833 over instances; 46.4 % of instances with >= 10 releases never pay;
               top 10 % of instances hold 70 % of the interest, top 20 % hold 89 %.
               SYNTHETIC baseline: Gini 0.779; 55.3 % never pay; top 10 % hold 57 %.
    DATA       BOTH         STRENGTH  STRONG (real); BY DESIGN (synthetic)
    FIGURE     04/real_i1_concentration.png ; 03/S5_patterns_vs_real_by_regime.png (Gini and
               "never pay" panels) ; 06/C1_panel_real_vs_synthetic.png
    SOURCE     insights/results/l2_temporal_structure.txt ; insights/new/results/n7_panel.csv

A2  Memory does not fade: interest is a persistent trait of the instance
    STATEMENT  An instance that paid interest is 3 to 4 times likelier to pay again, and the
               increase is the same whether the earlier event was 1 or 6 releases ago. More past
               events mean a higher chance (dose-response).
    EVIDENCE   REAL: P(event | event at lag 1..6) = 0.23, 0.21, 0.20, 0.24, 0.25, 0.22 against
               0.07 without an earlier event; by number of past events 5 % (0), 9.5 % (1),
               12.6 % (2), 20.7 % (3-4), 43.7 % (5+). SYNTHETIC baseline: 0.33, 0.34, 0.29
               (lags 1, 3, 5) against 0.09. A decaying (self-exciting) memory was tested and
               rejected on the real data.
    DATA       BOTH         STRENGTH  STRONG (real); BY DESIGN (synthetic)
    FIGURE     04/real_i2_memory.png ; 03/S5_patterns_vs_real_by_regime.png (P(ev|ev,lag1)) ; 06/C1
    SOURCE     insights/results/l2_temporal_structure.txt ; insights/results/l2_memory_lags.csv

A3  Debt is avoided, not attractive: it receives far fewer edits than its size predicts
    STATEMENT  The share of all edits that falls into debt regions is much smaller than the share
               of the code that debt regions occupy (enrichment below 1).
    EVIDENCE   REAL: debt regions are 31.8 % of the code and receive 12.3 % of the added or
               modified lines: enrichment 0.39, below 1 in all 9 repositories (0.26 to 0.85).
               SYNTHETIC baseline: enrichment 0.29.
    DATA       BOTH         STRENGTH  STRONG (real; line counts are approximate); BY DESIGN (synth.)
    FIGURE     04/real_i3_enrichment.png ; 03/S5_patterns_vs_real_by_regime.png (enrichment panel)
    SOURCE     insights/results/l2_enrichment.txt ; synthetic_dataset/insight_check.md

A4  No contagion inside a file
    STATEMENT  Whether another debt instance in the same file paid interest last release does not
               change the chance that this one does.
    EVIDENCE   REAL: ratio 1.08 (7.1 % against 6.5 %); instances that paid themselves 22.7 %.
               SYNTHETIC baseline: 0.79. (Only the synthetic "contagion" regime has a ratio of 1.8.)
    DATA       BOTH         STRENGTH  MODERATE
    FIGURE     03/S5_patterns_vs_real_by_regime.png (neighbour-ratio panel) ; 06/C1
    SOURCE     insights/results/l2_temporal_structure.txt (section 4)

A5  The release clock cannot be predicted from the past inside a project
    STATEMENT  Which releases are busy is random from one release to the next; the total interest
               of the next release cannot be predicted from the previous release.
    EVIDENCE   REAL: within-project correlation of the release event rate with the previous
               release -0.01, of the log total interest -0.06; R2 of the next total < 0.
               SYNTHETIC baseline: autocorrelation 0.00; R2 0.03-0.06 (0.15 only in the "ar_clock"
               regime, by design).
    DATA       BOTH         STRENGTH  STRONG (real)
    FIGURE     04/real_i5_where_when.png ; 03/S5_patterns_vs_real_by_regime.png (ICC release)
    SOURCE     insights/results/l2_release_clock.txt ; insights/synthetic/results/s3_timeseries.txt

A6  Persistence is close to the ceiling of "where"; what is left is "when"
    STATEMENT  Ranking by interest already paid reaches about the share that ranking by each
               instance's true long-run rate would reach; the rest of the gap to a perfect order is

    EVIDENCE   REAL, top 20 %: persistence 39.1 %, true long-run rate (uses the future) 37.8 %,
               perfect order 95.8 %, random 20 %. SYNTHETIC baseline (random ties): persistence 57.6 %, the

A7  The clean twin makes a debt change visible; a single snapshot cannot
    STATEMENT  The debt change is tiny against the natural change of a project; only the difference

    EVIDENCE   REAL: the median patch changes 9 lines in 1 file = 0.086 % of the project's lines;

               older version of its host has cosine similarity 1.00 (signature identical).
               SYNTHETIC: the delta (child - parent) gives 0.94 (random split), 0.96 (held-out
               project), 0.92 (temporal); the child alone 0.76, 0.76 and 0.62: the snapshot loses
               14 points on later pairs, the delta barely.
    DATA       BOTH         STRENGTH  STRONG
    FIGURE     04/real_i8_drift.png ; 04/real_i9_context_augmentation.png ;

    SOURCE     insights/results/l1_drift.txt, l1_context_aug.txt ;
               insights/synthetic/results/s1_pairs.txt, s1_protocols.txt

A8  Models learn the template of an injected change, not the debt
    STATEMENT  A model that sees the code of a change recognises the pattern of the script or

    EVIDENCE   REAL: unseen-project accuracy 0.95 for scripted injections but 0.47 (about chance)

               held-out template; a CNN on the code image 0.97, 0.98 and 0.56; the 133 features
               0.94, 0.96 and 0.83. More pairs of the same templates stop helping at about 300
               (held-out-template accuracy 0.75 at 60 pairs, 0.84 at 300, 0.86 at 600, 0.83 at 1,321).
    DATA       BOTH         STRENGTH  STRONG
    FIGURE     04/real_i7_level1_generalisation.png ; 05/E1_code_image_cnn.png ;
               04/synthetic_sf5_pairs_level1.png ; 01/code_to_image_examples.png
    SOURCE     insights/results/l1_local_signal.txt, l1_origin.txt ;
               insights/synthetic/results/s1_pairs.txt, s1_words_invariance.txt ;
               insights/new/results/n2_cnn_code.txt

A9  A file-level graph or image sees only structural debt

R1  Region size predicts interest; size alone ties "interest already paid"
    STATEMENT  Larger debt regions are edited more often (exposure). A rule with no history,
               "largest region first", is as good as the persistence baseline.
    EVIDENCE   AUC of size alone for 'interest in this release pair' 0.664; Spearman of size with
               the event rate per instance 0.31-0.40. Capture in the top 20 / 30 / 50 % (123
               groups): persistence with random ties 38.3 / 47.6 / 67.0; persistence with size ties
               40.1 / 49.6 / 72.3; size only 40.1 / 51.4 / 73.4; shrunk event rate + size ties
               40.1 / 52.7 / 72.0; random 19.8 / 30.8 / 51.3. No difference between size alone and
               persistence is significant.
    DATA       REAL         STRENGTH  STRONG (it also explains why nothing beat persistence)
    FIGURE     02/R5_size_vs_persistence.png ; 04/synthetic_sf3_size_real_vs_synthetic.png
    SOURCE     insights/synthetic/results/s2_size.txt, s2_tiebreak_real.txt

CAVEATS THAT APPLY TO EVERYTHING
    - 9 real repositories and 61 real pairs (60 injected): intervals are wide (+-5 to +-10 points).
    - The real fix times are a model; the real bugs were checked by parsing only.

    - Interest is the effort implied by changed lines (COCOMO II nominal constants), not measured time.
    - The synthetic code is assembled from 11 archetypes and 23 templates; its histories are simulated.
    - Many looks were taken (protocols, budgets, feature sets); single p-values are not corrected.

====================================================================================================
PART J.  THE OUT-OF-THE-BOX INSIGHTS, AND WHAT TO DO NEXT FOR EACH
====================================================================================================
SELECTION RULE. An insight is listed here as out of the box only if (1) it contradicts or reframes
the usual assumption in the debt literature or one of my own earlier claims, (2) it is backed by the
REAL data (not only by the synthetic generator), and (3) it changes what should be built or measured
next. Confirmatory results are listed at the end of this part as "not out of the box".
Effort scale: S = hours, M = days, L = weeks.  Each next step has a success criterion that is fixed
BEFORE the experiment, so that the result cannot be argued afterwards.

J1  "Interest already paid" is mostly a size proxy                    [R1, R2, R3, X3]
    USUAL VIEW   Past interest shows a hot spot; use it as the baseline and as the prior.
    THE DATA     A rule with no history ("largest region first") ties it (40.1 % against 40.1 % in the
                 top 20 %); region size alone has AUC 0.66; frozen debt is small (17 against 51
                 lines); history overtakes size only slowly.
    CONFIDENCE   Strong on 9 repositories; intervals on the differences are wide.
    NEXT STEP    (1) Estimate the exposure law: a negative-binomial regression of events per release
                 on log size with the repository as a random effect, on the instance-release rows;
                 report the exponent beta (events ~ size^beta; beta = 1 is pure exposure).
                 (2) Add 15-30 more repositories with interest_exp/code (clone_repos.sh, run_all.py;
                 use the structural-smell definition for C/C++ and lizard-based smells for Python to
                 avoid SonarQube). FREEZE the scores first (size x shrunk event rate, alpha = 2,
                 persistence with size ties) and run them on the new repositories untouched.
                 (3) Report an exposure-adjusted interest ("interest per 100 lines per release") so
                 that debt of different sizes can be compared.
    SUCCESS      size x shrunk rate beats persistence with size ties by >= 3 points in the top 30 %
                 with a 95 % interval above 0, on repositories not used so far.   EFFORT  M

J2  Debt costs only where the team works: the "path of work" view      [A3, R2]
    USUAL VIEW   Repay the worst-smelling code first.
    THE DATA     Debt regions are 32 % of the code and receive 12 % of the edits; about half of the
                 instances never receive any; most debt costs nothing now.
    CONFIDENCE   Strong for the enrichment (line counts are approximate); the consequence is untested.
    NEXT STEP    Build features that have not been tried: the structural PROXIMITY of an instance to
                 code that changed recently: the share of the changed lines of the last 1 and 3
                 releases that lie in files importing, or imported by, the instance's file (the
                 dependency graph of pipeline/f_structure.py), in the same directory, or that
                 co-changed with it in earlier commits (git log). Test them against size x history
                 (held-out repositories and temporal). Also test whether debt is repaid where work
                 happens (repayment rate by recency of nearby work).
    SUCCESS      capture in the top 30 % improves by >= 3 points over size x shrunk rate, interval
                 above 0, under both protocols.                                      EFFORT  M

J3  The release clock is calibration of a project, not timing         [R6, A5, D3]
    USUAL VIEW   A busy last release predicts a busy next one; use project activity to predict when
                 debt will cost.
    THE DATA     No autocorrelation inside a project (-0.01); but "how busy has this project been"
                 lifts the pooled AUC from 0.63 to 0.72 (a between-project effect, no ranking gain).
    CONFIDENCE   Strong.
    NEXT STEP    (1) Use the clock where it works: judge the pooled probability by CALIBRATION (Brier
                 score, expected calibration error) with and without the project's recent base rate;
                 this is the budgeting use. (2) Test an exogenous clock proxy that is known BEFORE the
                 release and has not been tried: the release type from the version number (major,
                 minor, patch: 8.1.3 -> 8.1.4 is a patch) and the days between tags; hypothesis: patch
                 releases carry fewer events. (3) Fit a two-state (active / quiet) hidden Markov model
                 per project on the release totals to look for regimes.
    SUCCESS      a clock proxy that raises the within-project R2 of the log release total above 0.10
                 under leave-one-repository-out.                                    EFFORT  S-M

J4  The clean twin (a commit and its parent) is the scalable data path   [A7, A8]
    USUAL VIEW   Labelled debt data come from manual annotation or from injection.
    THE DATA     The delta to the twin isolates the change (a single snapshot cannot see it; the
                 change is 0.086 % of the project); injection leaves a template fingerprint.
    CONFIDENCE   Strong for the twin; the mining itself is untested.
    NEXT STEP    Mine NATURAL pairs: in the 10 repositories (then others) take commits that remove a
                 smell (a refactoring), remove a self-admitted-debt comment, or fix a security or
                 concurrency problem (SZZ fix commits are in project_dataset/project_details).
                 Compute the features of the TOUCHED functions in parent and child; label by detector
                 and commit message and check 100 by hand. Report accuracy per repository, per origin
                 (natural against injected) and per template; train on injected + natural, test on
                 natural pairs of a held-out repository.
    SUCCESS      accuracy above the majority class of the natural test set, with a held-out
                 repository and a held-out template.                                   EFFORT  L

J5  A linear model on the DIRECTION of the change solves the missing-class problem   [R7, C3]
    USUAL VIEW   Tree ensembles are best on small tabular data.
    THE DATA     Under leave-one-project-out the random forest scores 0.00 on boltons (only 2
                 concurrency pairs left in training); a logistic regression on the unit-length delta
                 scores 0.92 there and 0.64-0.67 overall, but 0.46-0.51 on the other 37 pairs, where
                 the forest scores 0.73-0.76.
    CONFIDENCE   Moderate and OPTIMISTIC: the transform was chosen while exploring these 61 pairs.
    NEXT STEP    (1) Validate it properly: nested leave-one-project-out, with the transform (raw /
                 sign / unit length / rank) and the regularisation chosen INSIDE the training folds.
                 (2) Build the hybrid: forest for classes with enough examples, linear model for rare
                 classes (or a stack), and report recall per class. (3) Test on the natural pairs of
                 J4 as an untouched set. (4) Scale the synthetic deltas down 44 times and repeat, to
                 see whether the effect is scale invariance.
    SUCCESS      >= 0.60 overall and >= 0.70 on the non-boltons pairs under nested validation.
                                                                                       EFFORT  S

J6  The synthetic benchmark is 44 times too visible, which is why nothing transfers   [D2, C4]
    USUAL VIEW   Synthetic data approximate real data.
    THE DATA     The same number of features move (35 against 34) but the real change is 44 times
                 smaller; a model trained on the benchmark scores 0.148 on the real pairs; pooling
                 the benchmark into training hurts (0.443 -> 0.393).
    CONFIDENCE   Strong.
    NEXT STEP    Rebuild the benchmark with realistic dilution: debt changes of 1-5 lines inside 10-100
                 times more code (embed each project in a larger host, or add heavy unrelated
                 commits), the size-exposure law of J1, event clustering and a stronger release
                 clock (J3) in the baseline regime, a thinner hot tail. Then repeat the sim-to-real
                 test and the panel (06/C1).
    SUCCESS      a model trained on the rebuilt pairs beats the real majority (0.426) on the 61 real
                 pairs, and the panel shows at most 2 "different" metrics (now 4).    EFFORT  M

J7  Evaluation insight: every ranking claim needs a size baseline and the same tie handling   [X2, X3]
    USUAL VIEW   Compare a model with "interest already paid".
    THE DATA     The apparent +8 points were a tie-break artefact; size alone ties persistence.
    CONFIDENCE   Strong (it is a correction of my own result).
    NEXT STEP    Write the evaluation protocol as a checklist and apply it to the talk and to any
                 paper: report (a) random, (b) size only, (c) persistence with the SAME tie-break as
                 the model, (d) held-out repository and temporal protocols, (e) a paired bootstrap
                 over groups, (f) the number of looks. Publish prioritization_eval.py and s2_size.py.
    SUCCESS      every ranking number in the talk comes with items (a)-(e).             EFFORT  S

J8  Template diversity, not the number of pairs, limits the type classifier   [A8, S7]
    USUAL VIEW   More labelled data help.
    THE DATA     Held-out-template accuracy saturates at 0.84-0.86 from about 300 pairs; three
                 templates are not recognised from the others (path_traversal 0.05, feature_envy
                 0.25, many-parameters 0.56); a CNN on the code image falls to 0.56 on a new template.
    CONFIDENCE   Strong on the synthetic data; the real counterpart is the origin effect (0.95 against
                 0.47).
    NEXT STEP    (1) Add new kinds of edits instead of more pairs: LLM-written variants of each type
                 (several prompts and models), the natural pairs of J4, and analogues of the rare
                 patterns (file-API misuse, zip-slip for path traversal). (2) Always report accuracy
                 per template and per origin. (3) Test a pretrained code encoder on the diff
                 (embedding + a linear head) with the held-out template as the main protocol: does a
                 pretrained model generalise where hand features and CNNs do not?
    SUCCESS      held-out-template accuracy above 0.83 (the 133 features) on the same split.
                                                                                      EFFORT  M-L
    RESULT (step 3, frozen CodeBERT, done): NOT MET. Held-out template 0.618 (features 0.828), real
                 pairs 0.295-0.344 (majority 0.426); averaging with the features 0.822. See C6 and
                 05/E7_codebert_embeddings.png. Not tried: fine-tuning (too few real pairs), a code model
                 that covers C/C++ (UniXcoder, CodeT5+), a learned fusion instead of an average. The
                 remaining route of J8 is steps (1) and (2): new kinds of edits and per-template reporting.

J9  Real debt may get busier later in its life, and its events clump   [R9]   (a LEAD, not a finding)
    THE DATA     Event rate 0.126 in the first half of life, 0.153 in the second (p = 0.044); 17 % of
                 the real instances are significantly clumped against 6 % of the synthetic ones.
    CONFIDENCE   Weak: one test among several; instances are (function, smell) pairs, so not
                 independent.
