# reproduce/: figures, scores and the script that regenerates them

Every plot and every number of the project (and of the report and talk built from it) can be regenerated from this repository. The report and the talk files themselves are not in the repository.

```
reproduce/
  regenerate.sh      runs every figure / score script that needs no git clones, then refreshes figures/ and scores/ (24 steps, about 3 minutes)
  MANIFEST.csv       every figure -> the script that makes it -> the image it comes from -> where it is used (report figure number, slide)
  SCORES.md          the headline numbers, read from the result files (regenerated, not typed)
  figures/           flat copies of the figures: report/ (the 56 figures of the report), talk_final/ (results, insights, scenarios), talk_earlier/ (earlier deck)
  scores/            the result files behind every number, by topic (csv / json / txt)
  tools/             collect_figures.py, collect_scores.py (called by regenerate.sh)
  requirements.txt
```

## Run
```
pip install -r reproduce/requirements.txt
bash reproduce/regenerate.sh            # FULL=1 bash reproduce/regenerate.sh  also runs the slow rule-discovery step (about 10 minutes)
```
`PYP` / `PYS` select the Python for plots / analysis (default `python3`). The scripts work in place on the folders of the repository and rewrite their figures and result files; seeds are fixed, so the content is identical to what is committed (checked: all 24 steps ran and the regenerated figures and result files were byte-identical to the committed ones).

## Needs the git clones of the studied repositories (not in this repository)
Mining the 34 repositories (`real_project_analysis/code/a0_clone_corpus.sh`, `a1_release_tables.py`, `a2_commit_mining.py`, `b1_natural_pairs.py`), extracting function text (`code_insights/code/c1_extract.py`, `c3_examples.py`), clone detection (`k1_clones.py`, `k3_example.py`), building the synthetic benchmarks and the CodeBERT embeddings. Their outputs are committed (`real_project_analysis/data/`, `code_insights/results/c1_features.csv`, `k1_*.csv`, `examples/`), so everything downstream runs without the clones. To rerun them, clone the repositories to `repos/` as in `a0_clone_corpus.sh`.

## Notes on the numbers
- Gain of size + history over persistence (33 repositories): +2.3 (20 %) and +3.0 (30 %) are against persistence **with size as tie-break** (intervals [-0.1, 4.6] and [0.8, 5.2]); against plain persistence the gain is 1.7 and 2.2 points (`SCORES.md`).
- Memory (an event after an event in the previous release pair), size and repository controlled: odds ratio 4.64 (2.52-8.54) in C/C++, 1.43 (0.91-2.24) in Python (`scores/real_33_repositories/memory_odds_ratio_by_language.csv`).
- Code-text traits are clear in C/C++ only; only the clone co-change repeats in both languages. Clone detection ran on every 4th release pair. Trait tests use "interest" (changed lines beyond growth), clone tests use "edited" (any changed line).
- The embedding comparison is unfinished: CodeBERT, GraphCodeBERT, UniXcoder and RoBERTa were embedded, CodeT5 failed to load its tokenizer, Qwen2.5-Coder was stopped, nothing was evaluated. Only the code is committed.
- The synthetic benchmark was tuned against its own acceptance tests; passing them (25 of 27, the first version 9 of 27) is a fit, not an independent test.
